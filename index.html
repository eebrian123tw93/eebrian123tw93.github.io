Strict Aliasing Rule Undefined Behavior

Posted on 2026-01-28 Edited on 2026-02-05

一、問題核心回顧

Strict aliasing rule 規定：不同型別的 pointer / reference 不得指向同一物件。

違反此規則：
- 屬於 未定義行為（UB）
- -O2 / -O3 會合法地產生錯誤行為
- -O0 正常只是「剛好沒被最佳化」
> 「這段程式碼永遠不會出現」，因此優化器可能 不會像你預期那樣正確讀/寫記憶體。

資料競態（Data Race）如何解 — C++ 工程筆記

一、什麼是 Data Race（重點）

兩個以上執行緒，同時存取同一個記憶體位置，且至少一個是寫入，又沒有同步機制
→ 未定義行為（UB）

在 C++：

  • Data race 不是「邏輯錯誤」
  • 是 語言層級的 UB
  • 編譯器可以假設「它不會發生」

編譯器最佳化導致問題（UB 筆記）

Posted on 2026-01-28 Edited on 2026-02-05

編譯器最佳化導致問題筆記（Undefined Behavior）

一、核心觀念

編譯器最佳化不是「照程式碼跑」，而是「照語言規範跑」。

在 C / C++ 中：

  • 未定義行為（UB）代表語言不保證任何結果
  • 編譯器可以假設 UB 不存在
  • 因此在 -O2 / -O3 下，編譯器可以：
    • 重排指令
    • 刪除看似「不可能發生」的程式碼
